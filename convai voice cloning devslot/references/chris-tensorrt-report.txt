# OmniVoice TensorRT: 32 steps, cloning retained

Measured 2026-09-27 11:28:51 +0100 on the same RTX 5090 / Windows machine.

## Result

The TensorRT transformer plus CUDA graph replay reduces automatic-voice median latency from **837 ms to 199 ms (4.20x faster)**. With a cached cloning prompt, latency changes from **818 ms to 323 ms (2.53x faster)**. Kokoro measured **83 ms** in this new run; accelerated OmniVoice remains **2.39x** its median latency. Ratios are ratios of pooled medians, not averages of per-prompt speedups.

| Route | Median latency | Median RTF | ASR WER |
|---|---:|---:|---:|
| Kokoro / preset | 83.3 ms | 0.013 | 3.79% (5/132) |
| OmniVoice PyTorch / auto | 837.4 ms | 0.110 | 6.82% (9/132) |
| OmniVoice TensorRT / auto | 199.4 ms | 0.027 | 1.52% (2/132) |
| OmniVoice PyTorch / clone | 818.2 ms | 0.133 | 3.79% (5/132) |
| OmniVoice TensorRT / clone | 322.9 ms | 0.050 | 3.79% (5/132) |


Each row contains five texts x three warmed repeats. Complete-file latency covers request dispatch through WAV writing, excluding model load, per-shape warm-up and initial reference preparation. RTF is wall seconds divided by output duration. The clone row uses a cached reference prompt. No step reduction, quantization to INT8/FP8, pruning, distillation or automatic fallback was used.

## What runs in TensorRT

The 28-layer Qwen3-based bidirectional denoiser and audio-logit projection run in TensorRT FP16. The same TensorRT core is called exactly **32 times** for every measured accelerated utterance. The graph has batch 2 for classifier-free guidance and dynamic sequence length 32–1536 tokens (optimization point 256). This is one target utterance at a time, not batch TTS.

Token/text embeddings, rotary positions, the iterative sampling/scheduling loop, voice-reference encoding, audio decoding and postprocessing remain in the existing PyTorch implementation. This is a hybrid engine, not a fully native TensorRT speech stack. It preserves the model's cloning inputs and full 32-step schedule. A non-default CUDA stream and per-length CUDA graph replay reduce launch overhead; up to eight shapes are cached. A new shape needs capture/warm-up; the benchmark and app perform that before measuring warm latency.

The reference-audio encoder produces the same reusable VoiceClonePrompt consumed by both routes. In the app, supply a WAV and exact matching transcript, or use the included synthetic reference. No reference ASR or internet access is required. Reference encoding happens once per worker/reference, then is cached. WAVs are limited to 1–20 seconds; 3–10 seconds of clean speech is preferable. Kokoro continues to use its preset voice and does not clone the upload.

## Numerical and speech checks

The exportable PyTorch wrapper matched the original forward on the initial test exactly (max absolute difference 0; argmax agreement 100%). The built TensorRT engine is **not bit-identical**. Nine comparisons of real target-region logits across steps 1, 16 and 32, lengths 64, 262 and 659, produced max absolute differences up to 0.750, mean absolute differences 0.063–0.073, and argmax agreement 76.1–92.3%. Outputs were finite. High raw cosine similarity (>0.999999) should **not** be treated as proof of equivalent token decisions: the large shared logit offsets make that statistic optimistic.

FP16 execution/fusion differences can change sampled tokens and the waveform, even at the same seed. The reduced argmax agreement is disclosed rather than treated as exact conversion parity. This prototype passed execution, finite-output, 32-call and transcription smoke checks; it has **not** passed a human perceptual-equivalence or speaker-similarity acceptance test.

## Reproduce / limits

- TensorRT 11.2.1.2, RTX 5090, FP16 model weights. Existing Python 3.12, torch 2.7.1+cu128, torchaudio 2.7.1+cu128, transformers 5.6.1, CUDA-capable installed TensorRT bindings. No global package changes. Full VoiceStudio requirements were not installed.
- VoiceStudio source commit `31975717b2d473eb0ddb672f43f3cfc07c800996`; OmniVoice model revision `c5fdb5ccb189668d56333f77ba2629f4cd7535f4`. The source checkout remains untouched; adapters are separate.
- Build: `python work/build_trt.py` from the workspace root. ONNX and PLAN remain in work/omnivoice-trt (~1 GB each). PLAN is hardware/runtime specific. Rebuild for a different GPU or TensorRT version. Fixed architecture assumptions are specific to this checkpoint.
- Validation: `python work/validate_trt.py`. It checks finite outputs/logit diagnostics and exercises cloned synthesis; it does not establish perceptual parity.
- Stop the app before benchmarking. Run `python outputs/voice-bench/benchmark_trt.py`, then `python outputs/voice-bench/analyze_quality.py --trt`, then `python work/build_trt_report.py`.
- Benchmark order: Kokoro, PyTorch, TensorRT; automatic then cloned modes; randomized jobs within modes. One worker engine resident at a time. Three repeats, fixed seed 42, speed 1.0, English. Per-text warm-up added to both OmniVoice routes. Fixed seed repeats measure timing stability, not varied voices.
- No streaming/first-audio metric, concurrent game load, objective speaker embeddings, temperature-controlled experiment, or cross-engine VRAM claim. Native and PyTorch allocation statistics are not directly comparable.
- No silent PyTorch fallback: unsupported combined token lengths fail with an actionable error. Single-request worker serialization prevents concurrent use of CUDA graph buffers. The eight-shape cache bounds context count; eviction synchronizes before releasing graph buffers.
