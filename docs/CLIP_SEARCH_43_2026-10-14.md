# Clip search for the remaining 43 voices, loudness-aware (2026-10-14)

**Status: applied to the runtime assets, not heard by anyone yet.** The OmniVoice references of the 43 voices (short, long and best) are the new loudness-aware picks, Pocket keeps its current picks, and all four reference sets are gain-matched towards -20 LUFS (ceiling -1 dBTP, a quiet set is never made quieter). The 29 report voices, `8ug8ear` and `jake-estevez` were not touched. The reference WAVs and the four autobest configs live under `runtime/` (not in git); the originals are in `runtime/backups/clip-search-43-20261014/`. The bridge reads the configs at start, so it needs a restart to pick them up.

## What was run

The 2026-10-07 search had already covered these 43 voices (Kaggle, likeness only; `docs/REFERENCE_DURATION_SEARCH_2026-10-07.md`), so the TODO line calling the status unclear was stale. They were searched again with the same method plus a loudness band in the selection score: same held-out split per voice (the cache keys match the earlier runs for all 86 voice-engine pairs), same combat-cleaned pool and effect exclusions, same duration caps (OmniVoice 10 s and 18 s at 16 steps), same ECAPA likeness on the same fresh lines, at least two whole clips, the shortest set within one standard error. Scores of sets rendered earlier were reused for the singles race and the growth; the final comparison re-rendered every finalist together with the earlier likeness-only picks, so old and new are compared on identical lines and seeds in one run (OmniVoice scores move by up to about 0.03 between renders of the same set, so the ECAPA figures here are not comparable with the 2026-10-07 table).

**Pocket was stopped on the user's decision** after 1 of 43 voices and every process it started was killed, so Pocket keeps its current picks. Its gain-matched references come from those picks; its partial loudness-aware result for `aaron` is in `runs3/pocket-student-v2-s2000-ema-decv2-loud/` and is unused.

**Loudness bonus** (`scripts/clip-search/loudband.py`, added to a set's ECAPA in every selection comparison; integrated LUFS of the reference as built, BS.1770-4):

- -22 to -18 LUFS full bonus (+0.03); between -18 and -16 the same bonus (nothing extra for louder); quieter than -22: -0.015 per dB; hotter than -16: -0.015 per dB.
- True peak above -3 dBFS: -0.010 per dB (this is the search bonus; the gain stage below uses a -1 dBTP ceiling); peak-to-loudness ratio under 11 dB (squashed or shouted): -0.004 per dB.
- A clip with clipping, silence or a noise floor above -48 dBFS is never a candidate; the combat, shouted-delivery, effect and media exclusions still apply.

## Findings

- **The game pool is level-matched.** Lines are mixed at about -23.6 LUFS: the median of 42 of the 43 voices lies between -23.4 and -25.1 LUFS, and the 10th to 90th percentile spans only 1 to 2 dB for most. Few clips sit in the -22 to -16 band (0 to 36 per voice; `jesse` is the exception, all hot at about -17.8). So selection alone moved the Omni sets by only a few tenths of a dB.
- **The gain stage** (`loud43/apply_loud43.py`): one linear gain towards -20 LUFS integrated, capped so the true peak stays at or below -1 dBTP (the EBU R128 ceiling), no limiter. Below -20 LUFS the gain is max(0, min(gain to -20, gain to the ceiling)), so a quiet set is never made quieter; a set whose peak is already over -1 dBTP keeps gain 0. Sets between -20 and -16 LUFS are left alone; sets hotter than -16 LUFS come down to -20 (only `jesse`; `robert-wilson`'s short set at -18.1 is inside the range and stays).
- **Most sets still end under -20 LUFS** because lines have isolated peaks: raising a set towards -20 pushes its peak past -1 dBTP first. Every such set is listed below.
